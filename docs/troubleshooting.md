# Troubleshooting

This page lists the problems people run into while installing tfbs-mcp, connecting it to Claude and registering their data, with the cause and the fix for each. The installation itself is described in the [README](../README.md#installation).

In most cases, run `tfbs-mcp --check` in the activated environment first. It names the problem.

| What you see | Why | Fix |
|---|---|---|
| `Command 'Check' not found`, `Check: command not found` or `The term 'Check' is not recognized` | The test prompt from step 4 was typed into the terminal instead of Claude's chat | Start Claude (`claude` in the terminal, or open Claude Desktop) and type the prompt into the chat |
| `No module named 'mcp.server.fastmcp'`, or `tfbs-mcp: mcp 2.x is installed` | mcp 2 renamed the API this server uses | `pip install "mcp>=1.28,<2"` in the same environment |
| `tfbs` shows a red X or `failed` in `/mcp`, or reconnecting gives `-32000` | The server crashed at startup | Run `tfbs-mcp --check`; fix the `FAIL` line |
| pip fails on `pybigtools` with `Failed to build a native library through cargo` | Python 3.14, which one dependency (pybigtools) cannot be built for yet | Recreate the environment with Python 3.13 |
| `No matching distribution found for torch` | An old Linux system (glibc older than 2.28, e.g. CentOS 7 or RHEL 7), where current PyTorch does not install | Use Python 3.11 and update pip (`pip install -U pip`); check glibc with `ldd --version` |
| `tfbs-mcp: command not found` / `The term 'tfbs-mcp' is not recognized` | The environment is not active | Run the activation line from step 1 |
| `Cannot find command 'git'` during `pip install` | pip needs git to fetch the package from GitHub | Install git (see [What you need](../README.md#what-you-need)) and run the install command again |
| `tfbs` missing from Claude Desktop, no error | The config file is not valid JSON, usually a single backslash or a trailing comma | Paste the block from `tfbs-mcp --check` again |
| Works in the terminal, not in the app | The config uses the bare name `tfbs-mcp` instead of the full path | Use the path that `tfbs-mcp --check` prints |
| Claude says it cannot run `tfbs-mcp --setup` because the command asks questions | `tfbs-mcp --setup` without `--non-interactive` asks for each path on the keyboard, and Claude's shell cannot answer | Run `tfbs-mcp --setup` yourself in a terminal with the environment active, or give Claude the paths so it runs `tfbs-mcp --setup --non-interactive` with flags (see [Tell Claude where your files are](../README.md#tell-claude-where-your-files-are)) |
| `{"error": "No reference genome FASTA configured."}` | The tool needs data you have not supplied | See [Registering your data](../README.md#registering-your-data) |
| `Compressed FASTA is only supported in BGZF format` | The genome is a plain gzip file; `hg38.fa.gz` from UCSC is one | `gunzip hg38.fa.gz` and register the uncompressed `hg38.fa` |
| `Could not read BED file ...: the gzip data cannot be decompressed (...)` from `tfbs_extract_loci` (or the bzip2, xz, zip or zstd data) | The compressed BED file is damaged or incomplete, for example a download that stopped early | Decompress it yourself (`gunzip`, `bunzip2`, `xz -d`, `unzip` or `zstd -d`); if that fails too, download the file again. Then run the call again with the plain or the new file |
| `Non-integer start or end in ...` from `tfbs_extract_loci` | The BED file has a tab-separated header line of column names (such as `chrom start end`) that does not start with `#`, `track` or `browser` | Delete that line, or ask Claude to remove it, and run the call again |
| `{"error": "tfbs_remap_validation runs the MEME Suite's fimo program for its FIMO leg, and fimo is not on the PATH of the MCP server. ..."}` (or the same from `tfbs_chipseq_method_comparison` or `tfbs_disease_variant_validation`) | These three pipelines run the `fimo` program itself; the tangermeme fallback is used only by `tfbs_fimo`. The MEME Suite has no native Windows build | Install the MEME Suite (<https://meme-suite.org/meme/doc/download.html>, or `conda install -c bioconda meme`) and put its `bin` directory on the PATH of the MCP server (and of the compute nodes for `slurm=true`; for Claude Desktop see the FoldX row); then restart Claude. On Windows, run the server under WSL ([install-windows.md](install-windows.md#tools-that-need-wsl)). For the ClinVar check you can instead leave `motif_file` empty with `TFBS_MOTIF_FILE` unset, which skips its FIMO leg |
| `{"error": "fimo not found on PATH, and no FIMO reimplementation (tangermeme or memelite) to fall back on"}` from `tfbs_fimo` | Neither the MEME Suite's `fimo` program nor tangermeme is available to the server. With tangermeme installed (the `viz` and `genomics` extras bring it), `tfbs_fimo` uses tangermeme's FIMO reimplementation (memelite, numba-based, shipped with tangermeme 1.x) and reports `"backend": "memelite"` | `pip install "tfbs-mcp[viz]"` in the server's environment, or install the MEME Suite (see [Registering your data](../README.md#registering-your-data)); then restart Claude |
| `{"error": "FoldX binary not found on PATH."}` | FoldX is a separately licensed program that the install does not bring, or the server does not see the folder it is in | Install FoldX as described in [Compute structure-based binding energy](../README.md#compute-structure-based-binding-energy): the program renamed to `foldx` (or `foldx5`) in the folder of the `tfbs-mcp` executable. Claude Code sees that folder when you start `claude` with the environment active. Claude Desktop starts the server with its own PATH: add a `"PATH"` entry to the `env` block of the `tfbs` entry that lists that folder first, then the system folders, e.g. `"PATH": "/Users/you/micromamba/envs/tfbs-mcp/bin:/usr/local/bin:/usr/bin:/bin"` on macOS or `"PATH": "C:\\Users\\you\\tfbs-env\\Scripts;C:\\Windows\\system32;C:\\Windows"` on Windows. Restart Claude |
| A file registered earlier is no longer found (`No reference genome FASTA configured.` and the like) after running `tfbs-mcp --setup` again | Each setup run replaces the whole `tfbs` registration with the paths given in that run | Run it again with every path (`--genome ... --motif ... --clinvar ... --foldx-pdb ...`), add any variable you set by hand again, and restart Claude. `claude mcp get tfbs` shows what is registered |
| Claude Code times out while the server starts | The server loads PyTorch and its other libraries before it answers, which takes about 7 to 9 seconds on a workstation (7.4 to 8.7 s measured on one Windows 10 machine with a CPU build of PyTorch); a slow disk or antivirus scanning the environment can stretch that past the client's limit | Set `MCP_TIMEOUT=60000` before starting `claude` |

If something goes wrong inside a tool, the error comes back as a normal answer such as `{"error": "...", "fix": "..."}`, not as a crash. If an answer looks wrong, ask Claude to show the raw tool response.
